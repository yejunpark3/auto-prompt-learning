# Loop 계획: 실손보험 텔레마케팅 자기개선 루프

목적: 월 9,900원 실손보험 가입자 최대화.
우선순위: ① 대화 자연스러움 > ② 스팸 신고 최소화 > ③ 목적 달성(가입) 최대화.
상위 지표를 해치는 하위 지표 개선은 채택하지 않는다.

## 0. 측정과 역할 분담
- 리뷰어(`reviewer.py`)는 통화마다 두 값만 낸다: `spam`(end_reason이 spam_reported_by_callee) / `achieved`(목적 달성 t/f, 신고 통화는 항상 f) + 근거 메모.
- 자연스러움은 리뷰어가 재지 않는다. 매 회차 사람(=loop를 돌리는 Claude)이 transcript를 직접 읽고 판단한다.
- 회차 지표: `spam_rate`, `achieved_rate`(`reviews.json`에도 기록), 종료 사유 분포, 평균 턴, 발신자 평균 발화 길이.

## 1. 원칙 (매 회차 지킨다)
- 프롬프트 최소화: 자연스러움 문제는 모델 설정·코드로 먼저 고친다. 프롬프트 추가는 한 줄 이내, 규칙 목록 금지.
- 공정성: 지표를 위해 수신자(callee_prompt, report_spam 도구 설명), 리뷰어 기준, 페르소나 샘플링을 느슨하게 바꾸지 않는다. 수신자·리뷰어 쪽 수정은 현실성 버그(역할 혼동, 형식 오류)일 때만.
- 사실 날조 금지: 위키(`상품/*` 읽기 전용)와 목적에 없는 숫자·연락처·URL·회사명 지어내기, 수신자 정보 유출(알 수 없는 이름·직업 언급)은 자연스러움 결함으로 센다.
- 회차당 변경 1개(코드 1건 또는 learner 1건). 원인과 효과를 구분하기 위해.
- 통화는 사용자가 직접 실행한다. Claude는 실행하지 않고 기록 분석과 수정만 한다. 커밋도 사용자가 요청할 때만.
- 변경과 관찰은 `tmp/loop_log.md`에 기록.

## 2. 준비 (루프 시작 전 1회)
1. [완료] 리뷰어 구현: `reviewer.py`, `learner.py`(`spam`·`achieved` 저장, `reviews.json` 비율), `prompts.py`(`REVIEW_REQUEST`, `LEARN_REQUEST` 우선순위 한 줄), `main.py` 연결.
2. 지표 스크립트 `tmp/loop_stats.py`: `--last N`으로 최근 N개 기록의 end_reason 분포, spam_rate, achieved_rate, 평균 턴, 발신자 평균 발화 길이(문장 수·글자 수), 루프성 종료(repetition_loop·max_turns·empty_response) 수를 출력. `review`가 없는 기록은 건너뛰고 개수를 표시.
3. 리뷰어 점검(첫 통화 묶음 후 1회): 기존 기록 몇 건을 `reviewer.review_call`로 다시 돌려 `achieved`가 사람이 읽은 판정과 맞는지, 같은 기록을 2번 돌려도 같은지 확인. 불일치가 크면 `REVIEW_REQUEST`의 달성 기준 문구를 고친다.
   - 도구: `uv run tmp/review_check.py [기록.json ...]` (기록당 2번 판정, 불일치 표시).
4. 기준선: 재작성한 프롬프트·위키(한빛손해보험, 읽기 전용 `상품/*`·`응대/거절대응.md`)로 사용자가 돌린 첫 10통화만 쓴다. 이전 기록은 삭제했다(3번 점검은 첫 10통화로 한다). 지표는 `tmp/loop_log.md` 0회차로 기록.
   - 이전 기록에서 이미 보인 문제(발화 5문장 안팎, 역할 혼동, 회사명·사실 날조)는 1회차 진단표 첫 줄에 해당하므로 첫 변경 후보다.

## 3. 회차 절차
사용자가 실행한 통화 묶음마다 아래를 수행한다. 권장 묶음은 10통화(`--n 10 --learn-every 10`, 목적 `"월 9,900원 실손보험 가입 권유"`).
1. 측정: `uv run tmp/loop_stats.py --last 10`. 직전 회차와 비교.
2. 정독(자연스러움 판단): 가장 길거나 이상한 통화 2~3건, 신고 1건(있으면), 달성 1건(있으면)의 transcript와 review를 읽는다. 확인 항목: 한 발화 길이, 같은 말 반복, 역할 혼동(자기 이름 부르기 등), 날조, 수신자 정보 유출, 끊을 때를 못 맞춤.
3. 학습 결과 확인: `round_NNN/learner.json`, `system_before/after.md`, 위키 diff에서 날조 사실 기입, 빈 학습, 300자 거절 반복, 읽기 전용 침범 여부.
4. 진단 → 변경 1개 (위에서부터 처음 걸리는 것)
   | 조건 | 다룰 곳 |
   |---|---|
   | 루프성 종료, 역할 혼동, 발화 3문장↑, 날조, 정보 유출 | 코드: `agent.py`(clean_utterance, 샘플링), `phone_call.py`(종료·마무리), 최소 프롬프트 |
   | spam_rate > 10% 또는 직전 대비 상승 | `learner.py` (후보 A·B) |
   | 위 둘 정상 | `learner.py`/위키로 달성률 (후보 C·D) |
5. 게이트: 학습 직후 묶음에서 spam_rate가 +10%p 이상 오르거나, 자연스러움이 눈에 띄게 나빠졌으면 `round_NNN/system_before.md`, `wiki_before/`로 되돌리고 로그에 "롤백" 기록. 되돌릴 때는 `상품/*`, `응대/거절대응.md`(읽기 전용)는 건드리지 않는다.
6. 기록: `tmp/loop_log.md`에 회차 번호, 지표 표, 관찰 2~3줄, 변경 내용과 가설, 롤백 여부.
7. 사용자에게 다음 통화 실행을 안내(명령어 포함). 배치가 끝나면 `uv run learner.py`로 대기열을 확인하고, 0건이 아니면(리뷰 실패로 10건이 안 찬 경우) `uv run learner.py --now`로 학습을 마친 뒤 다음 배치를 시작한다. 그렇지 않으면 학습이 다음 배치 중간에 실행되어 회차 비교가 깨진다.

## 4. learner.py 개선 후보 (필요할 때 하나씩)
- A. 신고·미달성 통화 근거 강화: 리뷰 메모뿐 아니라 마지막 몇 턴 발췌를 LEARN_REQUEST에 넣는다(신고 직전 무엇이 거슬렸는지).
- B. 자동 게이트: 다음 learn 때 직전 round 이후 통화 지표를 그 전 round와 비교, 악화면 `*_before`로 복원 후 학습. 결과를 learner.json에 기록.
- C. 학습 이력: 이전 2~3회차 변경 요약·지표를 LEARN_REQUEST에 넣어 같은 수정을 되풀이하거나 진동하지 않게.
- D. 위키 성장: 달성 통화에서 통한 말(반론 처리, 혜택 설명)을 `응대/` 아래 문서로 쌓도록 지시. 읽기 전용 문서와 날조 금지는 유지.

## 5. 종료 조건
- 3회차 연속 루프성 종료 0, 정독에서 자연스러움 문제 없음, spam_rate ≤ 10%이고 achieved_rate가 더 오르지 않으면 멈추고 사용자에게 보고.
- 같은 문제가 3회차 연속 해결되지 않으면 멈추고 사용자에게 방향을 묻는다.
